The Design tab as a canvas you can move around

Owner report: “all the designs get laid out vertically, you can't move them around, and you can't zoom using a touchpad or mouse.” This keeps the toolbar, the screens list and the inspector as they are, and turns the column of rows into a canvas: zoom where you point, pan with the gestures you already use, put boards where you want them. It opens in today's layout, so nothing changes until you move something.

Where the layout lives

Positions persist per project in .styx/designs/canvas.json, next to the screens they place. It is versioned and zod-validated in core, like .styx/project.json, and written only through a named command (design.setLayout, the same no-follow write rules as design.write, debounced after a move ends). Because it sits in the design task's worktree, Styx commits it with the screens and it lands with them: the layout travels with the repo and a teammate opens the same arrangement.

{
  "version": 1,
  "boards": {
    "checkout/desktop.wire.html": { "x": 0,    "y": 0 },
    "checkout/desktop.html":      { "x": 1360, "y": 0 },
    "checkout/phone.html":        { "x": 2720, "y": 0 }
  }
}
  • Coordinates are canvas pixels at 100%, multiples of 8. A board with no entry is placed by the rule below; an entry whose file is gone is dropped on the next write.
  • No file, or one that fails validation, means today's layout. It is never an error the person sees.
  • Zoom and pan are a person's view, not the project's: they stay in the ui-store, keyed by session, like drafts.
  • Tidy up rewrites the file with today's layout (and can be undone).

New screens from the agent

A board the agent adds never lands on top of another. A new size or fidelity of an existing screen goes right of that screen's rightmost board; a new screen starts a row under the lowest board, at the left edge. Either way it then steps right in 8px until it overlaps nothing (with the usual gap). The view does not jump: a toast says what arrived and offers Show it. The placement is written to canvas.json so it stays put.

Select keeps working at any zoom

Select (V) and area select read the pointer in board coordinates (screen offset divided by the zoom), so a click picks the same element and an area box holds the same elements at 10% or 400%. Outlines, the area box and its tag divide their widths by the zoom so they stay crisp. The picture sent with Tell Claude is captured from the box on screen, as today. Space + drag and middle drag still pan while Select is on; a board's name still moves it.

For review

  • Both is added to Wireframe / Hi-fi and is the default here, so variants can sit side by side. Filters hide boards in place; they never re-flow the layout. If you'd rather keep Hi-fi as the default, the canvas behaves the same.
  • Board names keep their size on screen at every zoom and read “Screen Size · Fidelity”, since a board can leave its row. The row headings go.
  • A plain drag on empty canvas pans. Picking several boards with a box is left for later; it would take this gesture.
