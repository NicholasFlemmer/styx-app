Design before you build, and point at what to fix

A Design tab where your agent draws the screens first, as wireframes or high fidelity, at desktop and phone size, in your type and colours. Select anything to change it yourself or to tell the agent exactly what to fix, then hand the designs over to build. The same Select to fix works on the running app in Preview. And the tabs go in the order you choose.

Designs are files in the laneEach screen is a page the agent writes in the lane’s branch, with the design’s tokens beside it (colours, type, corners). Kept with the work and landed with it.
Point, don’t describeSelecting something hands the agent the screen, the element and a picture of it, in Design and in Preview. “Make this sticky” is enough.
Handover is one stepPick the screens, add a note, start. The agent builds them with the design’s tokens and Preview opens beside the design.

1 · Every screen at once, in your type and colour

The Design tab gives the canvas the room: the project nav steps aside (it is back on the other tabs, or with ⌘\). Screens on the left; every one on the canvas at each size. Aa opens Type and colour: colours, typefaces, the type scale, corners and spacing, applied to every screen at once and saved as the design’s tokens.

TodayThere is no design step: the agent goes straight to code, and Preview only has something once the app runs.

9 · Two kinds of task, linked

A task is a Design task or a Build task, chosen when you start it. Build it on a design starts a build task branched from the design (so it has the files) and links the two: the design says who is building it, the build says which design it is from. Change the design afterwards and Styx tells the build task what changed, with the element; the build card shows the message arrive. A fix picked in Preview goes to the build task; mark it “a design problem” and it goes to the design task instead.

TodayTasks are independent: one task’s agent can message another, but nothing links a design to its build.
